# llm-motion-graphic

말로 적은 움직임이 GSAP 이즈가 되고, 그 이즈가 공을 움직이고, three.js가 그 화면에 룩을 입힌다.
Claude와 모션을 얼마나 섞어 쓸 수 있는지 보려고 만든 판이다.

```bash
node serve.mjs
```

`http://localhost:7500`. 빌드 도구는 없다. ES 모듈과 importmap으로 three.js r186, GSAP 3.15를
CDN에서 바로 읽는다.

## 한 줄이 무엇인가

| 자리 | 보이는 것 |
| --- | --- |
| 왼쪽 그래프 | 속도 그래프. 애프터 이펙트 그래프 에디터의 Speed Graph와 같다. VALUE로 바꾸면 위치 그래프 |
| 이름 옆 칸 | 그 말을 옮긴 GSAP 표기. `back.out(1.8)` 같은 것 |
| 트랙 위의 점 | 간격표. 같은 시간마다 공이 있던 자리. 촘촘하면 느리고 성기면 빠르다 |
| 잔상 | 방금 지나온 자리. 길수록 빠르다 |
| 공의 늘어남 | 빠를수록 가로로 늘어난다. 서 있을 때는 동그랗다 |

모든 공이 같은 시계를 본다. 같은 순간에 떠나 같은 순간에 닿으므로 줄마다 다른 것은 그
사이를 어떻게 지나가느냐뿐이다. 그래프 칸 위를 끌면 시간을 손으로 움직인다.

트랙의 세로 눈금 둘이 출발과 도착이다. 트랙은 그보다 넓다 — 스프링은 목표를 37%나 지나치고
예비 동작은 11% 뒤로 물러나는데, 그 넘침이 이 무대가 보여주려는 것이라 잘리면 안 된다.

## 움직임은 GSAP, 보이는 것은 three.js

둘은 숫자 하나로만 만난다.

```
motions.js ── GSAP 타임라인 ──▶ proxies[i].p  (0 → 1)
                                     │
                                     ▼  틱마다 읽기만 한다
looks.js ──── 톤 매핑·블룸·보정 ──▶ stage.js ──▶ 화면
```

GSAP은 공을 모른다. 줄마다 `{ p: 0 }` 하나를 0에서 1로 옮길 뿐이다. 그 p를 공의 자리로,
그래프 위 점으로, 늘어남으로 바꾸는 것은 무대가 한다. 그래서 움직임을 바꿔도 룩은 그대로고
룩을 바꿔도 움직임은 그대로다.

재생 장치(`main.js`)는 열두 타임라인을 한 마스터 타임라인에 나란히 걸고
`repeat: -1, repeatDelay`로 되풀이한다. 재생·멈춤·손으로 끌기는 전부 그 마스터 하나에 대고 한다.
그래프도 같은 GSAP 타임라인을 멈춰 두고 끌며 잰 것이다 — 그래프에 그려진 것이 곧 GSAP이 실제로
움직이는 것이다.

## Claude가 끼어드는 자리

`src/motions.js` 가 전부다. 한 줄 한 줄이 말과 GSAP의 짝이다.

```js
{
  id: "overshoot",
  name: "OVERSHOOT",
  words: "목표를 지나쳤다가 되돌아와 앉는다. 탄력 있는 도착",
  ease: "back.out(1.8)"
}
```

`words` 는 사람이 할 법한 말이고 `ease` 는 그 말을 GSAP으로 옮긴 것이다. 새 움직임은 말로
설명하면 된다. "무거운 문이 천천히 열리다가 끝에서 쿵 하고 멈추는 느낌" 같은 식으로. Claude가
여기에 한 줄 더하면 화면이 그래프와 공을 알아서 그린다.

### 말이 GSAP이 되는 네 갈래

| 말 | 옮기는 방법 | 예 |
| --- | --- | --- |
| 이미 이름이 있는 느낌 | 이즈 이름을 고른다 | 오버슈트 `back.out(1.8)`, 바운스 `bounce.out` |
| 모양으로 설명되는 느낌 | 핸들을 적는다 | 엠퍼사이즈드 `CustomEase("0.05,0.7,0.1,1")` |
| 물리로 설명되는 느낌 | 함수로 푼다 | 스프링 `spring(0.3)` — 감쇠 진동 |
| 이야기로 설명되는 느낌 | 타임라인으로 잇는다 | 머뭇거림 — out → 쉼 → inOut |

```js
// "가다가 한 번 멈칫하고, 마음을 고쳐먹은 듯 다시 간다"
timeline: (tl, target) =>
  tl
    .to(target, { p: 0.46, duration: 0.38, ease: "power2.out" })
    .to(target, { p: 1, duration: 0.44, ease: "power2.inOut" }, "+=0.18")
```

마지막 줄이 LLM이 가장 쓸모 있는 자리다. 이름 있는 느낌은 GSAP이 거의 다 가지고 있고, 물리는
공식이 있다. "마음을 고쳐먹은 듯"은 어디에도 없다 — 그것을 트윈 둘과 쉼 하나로 쪼개는 것이
말을 아는 쪽의 일이다.

GSAP에 없는 것은 `src/curves.js` 에 둔다. 진짜 스프링과, 부드러운 곡선을 시간만 계단으로 끊는
`stepped` 두 가지뿐이다. GSAP의 `steps(8)` 은 직선을 끊어 곡선이 사라진다.

## 룩

같은 움직임에 다른 현상을 건다. 1–4 키로도 바꾼다.

| 룩 | 톤 매핑 | 블룸 | 보정 |
| --- | --- | --- | --- |
| CLEAN | Neutral | 없음 | 없음. 곡선을 판단할 때 |
| GLOW | ACES | 좁고 강하게 | 차가운 어둠, 채도 조금 올림, 비네트 |
| FILM | AgX | 붉게 번짐 (헐레이션) | 따뜻하게 들뜬 검정, 채도 뺌, 입자 |
| PAPER | Neutral | 없음 | 밝은 종이, 옅은 비네트와 입자 |

그리는 순서는 장면 → 블룸 → 톤 매핑(`OutputPass`) → 색보정(`GradeShader`)이다. 블룸은 톤 매핑
전의 선형 HDR에서 해야 밝은 것만 번지고, 색보정은 톤 매핑 뒤의 화면 공간에서 해야 대비와 리프트가
의도한 만큼 선다. 색보정가가 일하는 순서와 같다.

줄마다의 색은 OKLCH로 고른다. HSL로 색상만 돌리면 노랑은 밝고 파랑은 어둡게 보여, 밝은 종이
위에서 노랑 줄 이름이 사라진다.

새 룩은 `src/looks.js` 에 한 벌 더하면 된다. 무대 색, 빛, 보정 세 층이다.

## 주소로 순간 건네기

```
http://localhost:7500/?look=film&t=0.48
```

그 룩으로, 그 순간에 멈춘 채로 연다. 같은 장면을 룩만 바꿔 나란히 두고 볼 때 쓴다.

## 알아 둘 것

- **트윈은 처음 그려질 때 출발값을 읽는다.** 타임라인을 새로 짤 때 공이 중간에 있으면 거기서
  출발하는 트윈이 된다. 새로 짜기 전에 p를 0으로 돌려 둔다.
- **DURATION은 `timeScale` 이 아니라 새로 짜서 바꾼다.** 마스터를 통째로 늘이면 앞뒤의 쉼까지
  늘어나, 짧게 돌릴 때 도착한 공을 볼 틈이 없어진다.
- **three.js의 ACES는 노출을 0.6으로 나눈다.** 1.15만 줘도 두 배 가까이 밝아져 공이 하얗게 탄다.
- **블룸 반경을 키우면 화면 전체가 뿌옇게 뜬다.** 가장 흐린 층이 두꺼워지기 때문이다. 선이 많은
  화면일수록 좁게 쥔다.
- **글자는 HTML이라 보정을 거치지 않는다.** 색만 룩을 따라가게 넘긴다.
- **보이지 않는 탭에서는 느리게 간다.** 브라우저가 프레임을 거의 안 주고, GSAP은 긴 틈을 33ms로
  줄여 센다(lag smoothing). 버그가 아니다.

## 파일

| 파일 | 맡은 것 |
| --- | --- |
| `src/motions.js` | 말과 GSAP의 짝. 여기만 고치면 된다 |
| `src/curves.js` | GSAP에 없는 이즈(스프링, 계단)와 표본 읽기 |
| `src/looks.js` | 룩 네 벌과 색보정 셰이더 |
| `src/stage.js` | three.js 무대. 그래프, 트랙, 공, 후처리 |
| `src/main.js` | GSAP 마스터 타임라인, 다이얼, 손으로 시간 끌기 |
| `serve.mjs` | 정적 서버. riso-graphic 것과 같다 |
